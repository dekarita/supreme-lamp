## Honest limitations (F56-d owns the real thing)

- **Fetch is a stub.** `src/lib/fetchStub.ts` performs **no network call**, takes
  no byte budget and returns a typed `F56D_NOT_IMPLEMENTED` outcome; the card
  button is a real, clickable affordance that answers with the localized
  "coming in F56-d" toast and records a pending rail row. The frozen F56-c gate
  refuses the endpoint literal in executable `src/` code (comments and tests may
  name it); the stub keeps that refusal intact, so the endpoint is named only in
  comments. F56-d replaces this one module.
- **Own credentials are UI-only.** The modal never submits and never persists:
  the password lives in store memory, is wiped on `Escape`/close **and**
  immediately after the stub submit. No credential is written to any storage.
- **The 5-minute clock is the stub.** Every transition is computed by the pure
  `src/lib/search/progressiveLab.ts`; F56-d can drive the same functions from
  real adapter events without touching the component.
- **Adapter roster derivation.** `payloads/search-sources/` and the runtime
  registry are F56-b substrate and are not in `main`, so the Advanced adapter
  selection is derived from the frozen `search.sources.*` i18n labels (28
  entries, camelCase key → kebab-case `adapterId`), with a Vitest cell pinning
  the derived count. No descriptor is invented.
- **URL surfacing.** Only absolute `https://` URLs are rendered or linked
  (`validatedHttpsUrl`); anything else is explicitly withheld, because F56-c has
  no allowlist to validate against and the locked rules forbid an unvalidated
  download/purchase URL reaching the client.

## Decisions overwritten

- **A1 (in `decisions.md`, overwritten in place):** the size slider's initial
  default is now `0 = no cap` instead of `10 GB`. The wire semantics (`0` = no
  cap, positive = inclusive maximum) are unchanged and `backend.json` stays
  byte-frozen; the plan-era 10 GB value survives only as the named constant
  `A1_PLANNED_DEFAULT_MAX_SIZE_BYTES`.
- **Frozen id locks stay frozen.** The 71 `f56.search.*` + 21 `f57.explorer.*`
  entries are byte-identical; the v2 redesign appends its own arrays
  (`F56C_V2_SEARCH_IDS`, `F57_EXPLORER_V2_IDS`) and the gate asserts both the
  frozen size (71 + 21) and collision-freedom of the new ids against the 219-id
  registry (raw and dashed forms).
